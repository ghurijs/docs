Model fields are imported from `@ghuri/orm` (file fields from `@ghuri/storage`) and passed to
`Model({ … })`. See [Models and fields](/docs/topics/models/) for how they are used.

```ts
import { Model, CharField, ForeignKey, CASCADE } from '@ghuri/orm'

export class Post extends Model({
  title: new CharField({ maxLength: 200 }),
  author: new ForeignKey(() => User, { onDelete: CASCADE }),
}) {}
```

:::tip[If you know Django]
Field classes have Django's names. Options are camelCase: `max_length` → `maxLength`,
`auto_now_add` → `autoNowAdd`, `on_delete` → `onDelete`, `related_name` → `relatedName`,
`db_index` → `dbIndex`. The related model is a function (`() => User`) or a string
(`'auth.User'`) so circular imports work. Column names are derived as `snake_case` from the
property name (`createdAt` → `created_at`).
:::

## Common options

Accepted by every field.

| Option | Type | Default | Description |
|---|---|---|---|
| `null` | `boolean` | `false` | Store SQL `NULL` for missing values. The TypeScript type becomes `T \| null`. |
| `blank` | `boolean` | `false` | Allow empty values in validation (serializers, admin forms). |
| `default` | `T \| () => T` | none | Default value, or a function called for each new instance. |
| `dbDefault` | `T \| SQL` | none | Default computed by the database (`DEFAULT` clause). |
| `choices` | `Array<[value, label]> \| enum object` | none | Restrict values; the admin renders a select. |
| `primaryKey` | `boolean` | `false` | Make this the primary key. Implies `null: false`, `unique: true`. Disables the implicit `id`. |
| `unique` | `boolean` | `false` | Add a unique constraint. |
| `dbIndex` | `boolean` | `false` | Create an index on the column. |
| `dbColumn` | `string` | snake_case of the name | Column name override. |
| `editable` | `boolean` | `true` | `false` hides the field from the admin and from `ModelSerializer` writes. |
| `helpText` | `string` | none | Shown in the admin and in OpenAPI descriptions. |
| `verboseName` | `string` | derived from the name | Human-readable label. |
| `validators` | `Validator[]` | `[]` | Extra validators run by `fullClean()` and serializers. |
| `errorMessages` | `Record<string, string>` | built-in | Override messages by code (`required`, `invalid`, `maxLength`, `unique`, …). |

Every model gets an implicit `id: new BigAutoField({ primaryKey: true })` unless another field
sets `primaryKey: true`.

## Field types

"TS type" is the value type on model instances. Column types are what the schema editor emits.

### Automatic primary keys

| Field | TS type | SQLite / D1 | Postgres |
|---|---|---|---|
| `AutoField` | `number` | `integer PRIMARY KEY AUTOINCREMENT` | `integer GENERATED BY DEFAULT AS IDENTITY` |
| `BigAutoField` | `number` | `integer PRIMARY KEY AUTOINCREMENT` | `bigint GENERATED BY DEFAULT AS IDENTITY` |
| `SmallAutoField` | `number` | `integer PRIMARY KEY AUTOINCREMENT` | `smallint GENERATED BY DEFAULT AS IDENTITY` |

`BigAutoField` values are returned as JavaScript `number`. They are exact up to
`Number.MAX_SAFE_INTEGER` (about 9 × 10<sup>15</sup>), which no realistic auto-increment reaches.

### Text

| Field | TS type | SQLite / D1 | Postgres | Specific options |
|---|---|---|---|---|
| `CharField` | `string` | `text` | `varchar(maxLength)` | `maxLength` (required) |
| `TextField` | `string` | `text` | `text` | `maxLength` (validation only) |
| `SlugField` | `string` | `text` | `varchar(50)` | `maxLength` (default 50), `allowUnicode`; indexed by default |
| `EmailField` | `string` | `text` | `varchar(254)` | `maxLength` (default 254); `EmailValidator` |
| `URLField` | `string` | `text` | `varchar(200)` | `maxLength` (default 200); `URLValidator` |
| `UUIDField` | `string` | `text` | `uuid` | Use `default: () => crypto.randomUUID()` |
| `GenericIPAddressField` | `string` | `text` | `inet` | `protocol: 'both' \| 'ipv4' \| 'ipv6'` |

SQLite does not enforce lengths, so `maxLength` is enforced by validation on every database.

### Numbers

| Field | TS type | SQLite / D1 | Postgres | Specific options |
|---|---|---|---|---|
| `IntegerField` | `number` | `integer` | `integer` | |
| `BigIntegerField` | `number` | `integer` | `bigint` | |
| `SmallIntegerField` | `number` | `integer` | `smallint` | |
| `PositiveIntegerField` | `number` | `integer` + `CHECK >= 0` | `integer` + `CHECK >= 0` | |
| `PositiveSmallIntegerField` | `number` | `integer` + `CHECK >= 0` | `smallint` + `CHECK >= 0` | |
| `FloatField` | `number` | `real` | `double precision` | |
| `DecimalField` | `string` | `text` | `numeric(maxDigits, decimalPlaces)` | `maxDigits`, `decimalPlaces` (both required) |

`DecimalField` values are strings (`'19.99'`) so no precision is lost to floating point. Use a
decimal library if you need arithmetic.

### Booleans, dates and times

| Field | TS type | SQLite / D1 | Postgres | Specific options |
|---|---|---|---|---|
| `BooleanField` | `boolean` | `integer` (0/1) | `boolean` | |
| `DateField` | `string` (`'YYYY-MM-DD'`) | `text` | `date` | `autoNow`, `autoNowAdd` |
| `DateTimeField` | `Date` | `text` (ISO 8601, UTC) | `timestamptz` | `autoNow`, `autoNowAdd` |
| `TimeField` | `string` (`'HH:MM:SS'`) | `text` | `time` | `autoNow`, `autoNowAdd` |
| `DurationField` | `number` (milliseconds) | `integer` | `bigint` | |

`autoNowAdd` sets the value when the row is created; `autoNow` sets it on every `save()`.
Both make the field non-editable. `QuerySet.update()` does not touch `autoNow` fields, as in
Django.

### Structured and binary data

| Field | TS type | SQLite / D1 | Postgres | Specific options |
|---|---|---|---|---|
| `JSONField` | `unknown` (or your generic) | `text` (JSON) | `jsonb` | `encoder`/`decoder` hooks |
| `BinaryField` | `Uint8Array` | `blob` | `bytea` | `maxLength`; not editable by default |

Type a `JSONField` with a generic: `new JSONField<{ theme: string }>({ default: () => ({ theme: 'light' }) })`.

### Files (`@ghuri/storage`)

| Field | TS type | SQLite / D1 | Postgres | Specific options |
|---|---|---|---|---|
| `FileField` | `FieldFile` | `text` | `varchar(100)` | `uploadTo: string \| (instance, filename) => string`, `storage` (alias), `maxLength` (default 100) |
| `ImageField` | `FieldFile` | `text` | `varchar(100)` | as `FileField`; validates that uploads are images |

The column stores only the file name. `FieldFile` exposes `name`, `url`, `size()`, `open()`,
`save(name, content)` and `delete()`. See [File storage](/docs/topics/file-storage/).

### Relations

| Field | TS type of the attribute | Column | Specific options |
|---|---|---|---|
| `ForeignKey` | `Promise<Related>` via `obj.author`; raw key at `obj.authorId` | `<name>_id`, type of the target key | `to`, `onDelete` (required), `relatedName`, `relatedQueryName`, `toField`, `limitChoicesTo` |
| `OneToOneField` | as `ForeignKey`; reverse accessor returns one object | `<name>_id` + unique | as `ForeignKey` |
| `ManyToManyField` | related manager (`obj.tags.all()`, `.add()`, `.remove()`, `.set()`, `.clear()`) | join table `<app>_<model>_<name>` | `to`, `relatedName`, `relatedQueryName`, `through`, `limitChoicesTo` |

`to` is either `() => ModelClass` or a string `'app_label.Model'`. Use `'self'` for
self-referencing relations. See [Relations](/docs/topics/relations/).

## `onDelete` behaviours

Exported from `@ghuri/orm`. Deletes are emulated by the ORM rather than delegated to database
`ON DELETE` clauses, so they behave identically on D1, SQLite and Postgres.

| Constant | When the referenced row is deleted |
|---|---|
| `CASCADE` | Delete the referencing rows too (recursively, firing `preDelete`/`postDelete`). |
| `PROTECT` | Refuse; raise `ProtectedError`. |
| `RESTRICT` | Refuse unless the referencing rows are also being deleted in the same cascade (Django's `RESTRICT` semantics). |
| `SET_NULL` | Set the key to `NULL`. The field needs `null: true`. |
| `SET_DEFAULT` | Set the key to the field's `default`. |
| `DO_NOTHING` | Do nothing in the ORM. The database may reject the delete if it enforces the constraint. |

Because the rules live in the ORM, they apply to deletes made through it (`instance.delete()`
and `QuerySet.delete()`, which collects related objects first, exactly like Django). A raw SQL
`DELETE` bypasses them.

## Validators

Import from `@ghuri/orm` and pass in `validators`:

| Validator | Checks |
|---|---|
| `new MinValueValidator(n)` | value `>= n` |
| `new MaxValueValidator(n)` | value `<= n` |
| `new MinLengthValidator(n)` | length `>= n` |
| `new MaxLengthValidator(n)` | length `<= n` (added automatically for `maxLength`) |
| `new RegexValidator({ regex, message?, inverseMatch? })` | value matches (or does not match) the pattern |
| `new EmailValidator()` | a valid email address (used by `EmailField`) |
| `new URLValidator({ schemes? })` | a valid URL (used by `URLField`) |
| `validateSlug` | letters, numbers, underscores and hyphens (used by `SlugField`) |

```ts
import { IntegerField, MinValueValidator, MaxValueValidator } from '@ghuri/orm'

rating: new IntegerField({ validators: [new MinValueValidator(1), new MaxValueValidator(5)] }),
```

A validator is any function `(value) => void` that throws `ValidationError`, so you can write
your own:

```ts
import { ValidationError } from '@ghuri/core'

const noShouting = (value: string) => {
  if (value === value.toUpperCase()) throw new ValidationError('Please do not shout.')
}
```

## The `Field` API

Admin, REST, agents and migrations rely on these public members. They are useful when you write
generic code over `Model._meta.fields`.

| Member | Description |
|---|---|
| `name`, `attname`, `column` | Property name, attribute holding the raw value (`authorId` for FKs), database column. |
| `model` | The model class the field belongs to. |
| `internalType` | `'CharField'`, `'ForeignKey'`, … |
| `null`, `blank`, `primaryKey`, `unique`, `editable`, `choices`, `helpText`, `verboseName`, `maxLength` | Option values. |
| `isRelation`, `manyToOne`, `oneToOne`, `manyToMany`, `relatedModel` | Relation metadata. `relatedModel` resolves lazily. |
| `hasDefault()`, `getDefault()` | Default handling. |
| `toPython(value)` | Coerce form or JSON input; throws `ValidationError`. |
| `validate(value, instance)` | Run built-in and custom validators. |
| `toDb(value, dialect)`, `fromDb(value, dialect)` | Convert to and from the database representation. |
| `deconstruct()` | JSON-able `{ type, options }` used by migrations. |
| `formHint()` | Widget hint for the admin (`'text'`, `'select'`, `'datetime'`, …). |
| `jsonSchema()` | JSON Schema fragment used by OpenAPI and agent tools. |
